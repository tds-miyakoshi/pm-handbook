# 04. WBS・RACI図・コミュニケーション計画書（Ⅲ-4.1 ／ 4.2 ／ 4.11）

> **WBSとRACIの鉄則（Ⅲ-4.1）**
> 1. **100%ルール**：WBSに記載されない作業はプロジェクトのスコープ外であることを顧客と合意する。
> 2. **40時間ルール**：最下位のワーク・パッケージ（WP）は、大規模案件であっても **1WP ＝ 40時間以内（約1週間以内）** を目安とする。
> 3. **1タスク1責任者の原則**：RACI図において、1つの作業に複数の責任者を置かない。またマトリクス体制では他部署要員のタスクも漏れなく記載する。

## 2. RACI図（責任分担マトリクス）（Ⅲ-4.1 (5)）

- **R（Responsible：実行責任）**：その作業を実際に遂行する責任者（**各行に必ず1名**）
- **A（Accountable：説明責任）**：成果物の承認・最終説明責任を持つ者（**各行に必ず1名**）
- **C（Consult：相談対応）**：知見を提供し相談に乗る者
- **I（Inform：情報提供）**：結果や進捗の報告を受ける者

| アクティビティ / 作業グループ | 顧客（ユーザ） | PM | PL（リーダ） | 開発チームA | 協力会社窓口 | 品質保証 / PMO |
| :--- | :---: | :---: | :---: | :---: | :---: | :---: |
| **1. 要件整理・業務課題提示（ユーザ責務①）** | **R / A** | C | C | I | I | I |
| **2. 要件定義書・仕様書の作成** | C | **A** | **R** | C | I | C |
| **3. 仕様書のレビューと計画日程通りの承認（ユーザ責務②）** | **R / A** | C | C | I | I | I |
| **4. 基本設計・詳細設計** | I | **A** | C | **R** | C | I |
| **5. サブシステム実装・単体テスト** | I | **A** | C | I | **R** | I |
| **6. 結合テスト・総合テスト** | I | **A** | **R** | C | C | C |
| **7. 運用テスト（受入テスト）・検収** | **R / A** | C | C | I | I | I |

## 3. コミュニケーション計画（5種類の主なミーティング）（Ⅲ-4.11）

> **注意事項**：
> - 電子メールは「送れば相手が読む」と過信せず、重要用件は直接対話（Face to Face）または受信確認を徹底する。
> - 外部委託先とのミーティングは **契約時に** 報告内容・頻度・場所・議事録承認方法を必ず合意する。

| 会議体名称 | 目的・議題 | 参加者 | 開催頻度・曜日 | 手段・場所 | 議事録担当・承認ルール |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **① チーム内ミーティング** | 進捗確認、連絡事項、問題共有、メンバの体調確認 | チームメンバ全員 | 毎日（朝礼15分）／毎週 | スタンドアップ／Web | チケット更新で代替可 |
| **② プロジェクト内ミーティング** | 複数チーム間の進捗・課題共有、ルール変更の周知 | PM、各チームリーダ、PMO | 毎週〇曜日 | 会議室／Web | PMO作成 → PM承認 |
| **③ 部門／事業本部／全社プロジェクト推進会議** | 部門間・全社での問題共有、エスカレーション解決策検討 | PM、所属長、事業本部長、PMO | 毎週 ／ 毎月 | 推進会議室 | 推進会議フォーマット（EVM・リスク報告） |

| **⑤ 外部委託先との定例ミーティング** | 委託先のWBS進捗確認、中間成果物品質確認、課題共有 | PM、PL、委託先現場責任者（窓口） | 毎週〇曜日 | 会議室／Web | 委託先作成 → 当社PM承認（※契約時に義務付け） |
