# PMハンドブック 改訂版 — 要点まとめ ＆ プレゼンテーションスライド

ソフトウェア開発・システムインテグレーション（SI）におけるプロジェクトマネジメントの心構え、実践的知識、管理技法を体系的にまとめた **「PMハンドブック 改訂版」** の学習・ナレッジ共有用リポジトリです。

PMBOK®（第5版）の知識体系をベースに、立上げ・見積・契約・WBS・リスク管理から、EVM（アーンド・バリュー・マネジメント）、CCPM（クリティカルチェーンPM）、チケット駆動開発（TiDD）、BABOK®要求分類、QC7つ道具・ESQRによる品質管理、出荷判定会議、終結・KPT振り返りまで、現場で直ちに役立つ実践ノウハウをスライドおよびドキュメントとして再構成しています。

## 🚀 スライドの閲覧方法

### 1. Webブラウザで閲覧（推奨）
本リポジトリで **GitHub Pages** を有効化すると、以下のURLで直接インタラクティブスライドを閲覧・プレゼンできます：
> `https://<ユーザー名>.github.io/<リポジトリ名>/`

※ ローカル環境では `index.html`（または `PMハンドブック_スライド.html`）をダブルクリックしてブラウザで開くだけで、スタンドアロンで動作します。

### スライドの操作方法
- **次へ進む**: `→`（右矢印）、`Space`、`PageDown`、または画面右下の `▶`
- **前に戻る**: `←`（左矢印）、`PageUp`、または画面右下の `◀`
- **全画面表示 (Fullscreen)**: `F` キー または `⛶` ボタン
- **スライド一覧表示 (Overview)**: `O` キー、スライド番号ボタン、または `⊞` ボタン（全92スライドをグリッド表示し、クリックでジャンプ）
- **特定スライドへの直接アクセス**: URL末尾に `#slide-10` のように指定可能

## 📚 カバーしている主な内容（目次構成）

### 序章：PM 憲章
- **プロジェクトの成功の定義**：ユーザの満足・会社の利益・プロジェクトの意欲向上のすべてを達成すること
- **PMの役割（3原則）** と **組織の役割（2原則）**

### Ⅰ. プロジェクト・マネジャーとは
1. **プロジェクト・マネジャーの仕事**：コスト・スケジュール・品質とPDCAサイクル
2. **プロジェクト開始前に準備すること**：作業着手前に確認すべき7項目
3. **プロジェクト・スコープ**：成果物スコープ（「何を」）とプロジェクト・スコープ（「どこまで」・WBS）
4. **SOW（Statement of Work：作業範囲記述書）とは？**：見積仕様書による代替と記載項目
5. **ステークホルダ**：利害関係者の相関と期待・利害の調整
6. **ステークホルダの支援を得る**：所属長・関係部署を巻き込むための6つの準備
7. **プロジェクトの難易度**：難易度を高める典型要因とリスク対策費・要員配置
8. **コンプライアンスへの配慮**：労働者派遣法と構内請負（偽装請負防止）、メール誤送信防止、顧客データ管理、SNSマナー
9. **社内（部門）ルールとプロセス**：組織のプロセス資産とプロジェクト管理共通ガイドライン
10. **エスカレーション**：問題の「芽」での早期報告と定量的根拠の提示

### Ⅱ. 立上げ
1. **プロジェクト分析・調査**
   - **1.1 プロジェクト情報収集**：見積仕様書・RFPの再精査と、未確定事項の洗い出し
   - **1.2 プロジェクト分析**：プロジェクト憲章として公式文書化する8項目（目的、計測可能な成功尺度、成果物、仮定と制約、リスク、大日程、ステークホルダ、案件審議委員会と出荷判定基準）

### Ⅲ. 計画
1. **見積**
   - **1.1 PMの責任** ／ **1.2 見積作業とは**（前提条件の明文化・開発原価見積の4ステップ）
   - **1.3 見積技法の種類**（類推・係数モデル［FP法］・ボトムアップ・三点見積り）
   - **1.4 コンティンジェンシー（プロジェクト）予備費**
   - **1.5 見積抜け・モレ**（見積書作成チェックシート11項目、協力会社選定）
   - **1.6 開発原価見積ベースで考えよう**（「価格ありき」の見積への対処4ステップ）
2. **契約**
   - **2.1 契約の種類とリスクとは**（請負・準委任・派遣の比較、工程別の望ましい契約形態、曖昧さの排除）
   - **2.2 スコープの変更**（経産省モデル契約書に基づく5つの実施ポイント、変更提案書・変更管理書）
   - **2.3 契約時のリスクとは**（不当条項、インプット不明確、価格逸脱、「成果物一式」の排除）
3. **プロジェクト憲章**：PMへの権限付与とスポンサ認可
4. **プロジェクト計画書**
   - **4.1 WBSを作成する**（100%ルール、階層構造、40時間基準、EVM連携、RACI図、クリティカル・パス）
   - **4.2 要員計画**（チームビルディング、プロジェクト内PMO） ／ **4.3 要員のスキル** ／ **4.4 協力会社選定**
   - **4.5 コスト計画**（原価構造とプロジェクト月別原価計画書）
   - **4.6 成果物計画** ／ **4.7 レビュー計画** ／ **4.8 変更管理計画** ／ **4.9 ステークホルダ分析**
   - **4.10 リスク管理計画**（リスクと不確実性のカーブ、CSA・リスク識別シート、リスク分布図、脅威への4戦略、領域別リスク一覧）
   - **4.11 コミュニケーション計画**（5種類の主なミーティングと情報共有の心得）
5. **統合管理（計画）**
   - **5.1 統合変更管理** ／ **5.2 変更管理計画**（トレーサビリティとインテグリティ） ／ **5.3 仕様の確定**（みなし承認ルール等） ／ **5.4 ユーザ要件の確定**（仕様変更低減の6原則）

### Ⅳ. 実施とコントロール
1. **キックオフ・ミーティング**：**1.1 目的と意義** ／ **1.2 社内向け・顧客合同キックオフのポイント**
2. **統合管理（実施）**
   - **2.1 進捗管理（EVM）**：PV・EV・AC・BAC、SPI・CPIの安全性評価、EACによる完成時総コスト予測
   - **2.2 クリティカルチェーンプロジェクトマネジメント（CCPM）**：TOC（制約理論）、人の6つの問題行動、5つの処方箋（選択と集中・ODSC・段取り八分・サバ取り・バッファ管理）
   - **2.3 変更管理**：変更管理の7ステップフロー、チケット駆動開発（TiDD：Redmine / Trac活用）
   - **2.4 要件管理**：BABOK®要求分類、モデリング手法とUSDM、非機能要件とSLA/SLO、典型トラブルとリスク回避10原則
3. **課題管理**：**3.1 課題とリスクの違い** ／ **3.2 課題管理表の運用（網掛け履歴管理）とRedmine活用**
4. **リスクコントロール**：**4.1 リスクの継続識別** ／ **4.2 監視の4大タイミング** ／ **4.3 リスク顕在化時の課題管理表への移行**
5. **品質管理**
   - **5.1 品質計画**（予防重視の原則、ISO9126の6大品質特性）
   - **5.2 品質管理**（管理図とメトリクス、特性要因図・マインドマップ、簡易FTA図・なぜなぜ分析、是正と記録）
   - **5.3 品質検査** ／ **5.4 品質保証（QA）** ／ **5.5 プロセス改善**
   - **5.6 品質改善事例**（IPA/SEC ESQRの5ステップ、コードレビュー作業実施率の可視化）
   - **5.7 出荷判定会議**（出荷判定書の構成と9つの確認項目）

### Ⅴ. 終結
1. **プロジェクトの終結**
   - **1.1 何をもって完了とみなすのか？**：終了状況の7項目確認、ユーザ検収、振り返り手法「KPT（ケプト）法」
   - **1.2 誰に何を報告すべきか？**：プロジェクト完了報告書と完了報告会、組織のプロセス資産への還流
